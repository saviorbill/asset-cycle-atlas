# 访问统计设置（看有没有人在用）

站点是纯静态托管（GitHub Pages），没有服务器日志，所以要靠**第三方 JS 埋点**。

已内置 `web/analytics.js`：**两个 ID 留空就完全不发请求**，填哪个开哪个。

---

## 方案对比

| | 百度统计 | Cloudflare Web Analytics |
|---|---|---|
| 国内可用性 | ✅ 最稳（国内节点） | ⚠️ 可用，偶尔慢 |
| 费用 | 免费 | 免费 |
| 需要账号 | 百度账号（实名） | Cloudflare 账号 |
| Cookie | 有 | **无**、不采集个人数据 |
| 能看什么 | 访客数/浏览量/来源/地域/页面/停留时长/设备 | 浏览量/访客/页面/来源国家/浏览器 |
| 广告拦截影响 | 少量被拦 | 少量被拦 |

> **建议：两个都开**。百度统计看国内明细，Cloudflare 做交叉验证（避免单一来源被拦导致误判「没人用」）。

---

## 一、百度统计（推荐先开这个）

1. 打开 <https://tongji.baidu.com> → 登录（百度账号，需实名）
2. **管理 → 新增网站**
   - 域名填你的站点域名（GitHub Pages 的 `saviorbill.github.io` 也可以）
   - 网站首页填完整地址
3. 添加后进入 **代码获取**，会看到一段代码，里面有一串 ID：

   ```html
   hm.src = "https://hm.baidu.com/hm.js?这里这串就是ID";
   ```

4. 把 ID 填到 `web/analytics.js`：

   ```js
   baiduId: 'abcd1234efgh5678',   // ← 粘贴那串 ID
   ```

5. 提交部署（`git add -A && git commit -m "analytics" && git push`）
6. 等 10–30 分钟，百度统计后台「实时访客」就能看到数据

**能看到的指标**：浏览量(PV)、访客数(UV)、新老访客、来源（直接/搜索引擎/外链）、地域、设备、停留时长、跳出率、逐小时曲线。

---

## 二、Cloudflare Web Analytics（可选，做交叉验证）

1. 登录 <https://dash.cloudflare.com> → 左侧 **Analytics & Logs → Web Analytics**
2. **Add a site** → 填你的站点域名（不需要把 DNS 托管到 Cloudflare）
3. 复制给出的 **token**
4. 填到 `web/analytics.js`：

   ```js
   cfToken: '你的token',
   ```

5. 提交部署，几分钟后后台就有数据

> 注意：这里只是用它的 JS beacon，**不需要把域名迁到 Cloudflare**。

---

## 三、怎么判断「有没有人在用」

打开任一个后台，看：

| 指标 | 含义 | 判断 |
|---|---|---|
| **日浏览量 PV** | 每天被打开的次数 | >0 说明有人访问 |
| **日访客数 UV** | 每天独立人数 | 你的关注重点 |
| **来源** | 直接访问 / 搜索引擎 / 外链 | 「直接访问」多 = 老用户在用 |
| **页面排行** | 哪些页面被看 | 知道用户最关心哪一块 |
| **地域** | 来自哪些省市 | 配合你的读者分布 |

**建议观察周期**：连续看 2 周，看趋势而不是单日数字（周一 vs 周末差异很大）。

---

## 四、注意事项

1. **广告拦截器**（如 uBlock / AdBlock）会拦掉统计脚本，实际数字通常比真实低 20–40%。
2. **爬虫/无 JS 环境**不计入。
3. 如果两边数字差很多（例如百度 100、Cloudflare 5），通常是某一方的脚本被拦 —— 以**较高的一方**作为下限估计。
4. 想更精确的话，可以在 Cloudflare 里看「国家/地区」分布，确认是不是真有中国访客。
5. 隐私提示：如果将来有付费/公开运营，建议在页脚加一行「本站使用访问统计」说明。
